# Wave 7: durable recovery across reopened stores and restarts

Owner: `recovery` test agent.

## What was built

`tests/test_brain7_recovery.py` independently exercises recovery of the
host-owned SQLite company brain. Expected state is produced by Mari Kit's pure
`plan_sync` reducer (the store is never used to build its own oracle), and every
test is deterministic: no network, no sleeps, and no shared interpreter state
except the `os.fork` process-death cases.

| Test | Recovery invariant pinned |
| --- | --- |
| `test_full_snapshot_checkpoint_continuation_survives_reopen` | A 3-page authoritative full snapshot is closed/reopened after **every** page; the decoded state, documents, and projection equal the pure planner's, including held cursor, checkpoint, and `full_seen` accumulation. |
| `test_partial_full_snapshot_reconciliation_after_reopen_deletes_absent` | A new full snapshot interrupted mid-run, reopened, and completed deletes a document absent from the terminal page with `absent_from_complete_snapshot`. |
| `test_incremental_checkpoint_continuation_drives_source_after_reopen` | An incomplete incremental page holds the durable cursor and persists `checkpoint`/`active_mode`; a reopened store resumes the connector from that checkpoint alone. |
| `test_partial_snapshot_mode_lock_survives_reopen` | The incomplete-mode lock (`full` vs `incremental`) survives a reopen and still rejects the wrong mode. |
| `test_process_death_during_partial_page_then_resume[after_documents/after_projection/before_commit]` | `os._exit` at each pre-commit stage leaves documents, projection, state, **and access counters** at the previous committed values; the same page can be re-planned and applied. |
| `test_process_death_during_partial_page_then_resume[after_commit]` | Death after commit is durable and advances the document epoch by exactly one. |
| `test_reopened_store_isolates_scopes_sources_and_users` | Documents, per-source sync state (including the partial lock), groups, and both epoch counters stay isolated by tenant/space/source/user across a reopen. |
| `test_document_and_membership_epochs_are_durable_and_idempotent` | Idempotent `set_groups` does not advance the membership epoch after a reopen; document edits advance only the document epoch, membership changes only the membership epoch. |
| `test_durable_answer_cache_is_shared_by_fresh_and_restarted_brains` | A record generated by a warm brain is served (`cache_hit=True`, identical answer/evidence) by reopened and concurrently opened fresh brains. |
| `test_durable_cache_invalidation_matches_fresh_and_warm_brains` | After a cross-connection body edit the first answering brain regenerates; the other reuses the new record; neither ever serves stale prose. Membership revocation is observed identically by both. |
| `test_deleted_document_invalidates_restarted_cache` | A deletion committed while the process is closed makes the reopened brain abstain instead of serving the old grounded answer. |
| `test_same_revision_acl_change_invalidates_warm_and_fresh_after_reopen` | A same-revision ACL move (revision body unchanged) invalidates both a warm reader and a fresh brain after reopen. |
| `test_durable_answer_cache_is_bound_to_scope_and_user_across_reopen` | Identical question/user cache keys in two tenants, and a no-membership user in the same tenant, never cross-serve persisted prose. |
| `test_stale_plan_after_reopen_writes_nothing` | A plan planned before another commit fails the optimistic generation check after reopen and writes nothing (no document, projection, or state change). |

## Findings

**No new recovery defects were found in the tested revision.** The completed tests passed against the planner/store/engine at the
hashes below. The positive results are themselves the finding: the durable
surface makes partial snapshots, checkpoint continuation, and cross-restart
answer reuse genuinely recoverable, including after real process death.

Verified non-findings (desired behavior held):

- Reopened state round-trips losslessly, including `manifest` fingerprints,
  `full_seen`, `active_mode`, `checkpoint`, and `cursor`; reconciliation and the
  `absent_from_complete_snapshot` reason replay exactly.
- A rolled-back or killed incomplete page leaves no phantom document-epoch bump,
  so a warm reader is not spuriously invalidated and no stale answer is served.
- The durable answer cache is shared across independent connections: the first
  reader regenerates a changed view, later readers reuse the persisted record,
  and no reader serves prose whose digest/evidence no longer matches live state.
- Scope/source/user isolation is structural for documents, sync state, groups,
  and both epoch counters, and survives reopens.

Residual limits (documented, not defects): recovery assumes all writers use the
store methods (raw SQL bypasses the epoch counters), assumes brain instances are
discarded/closed before replacing a database file, and treats the checksum as
accident detection rather than authentication. Hardware power-loss and online
restore are explicitly out of scope for the example.
